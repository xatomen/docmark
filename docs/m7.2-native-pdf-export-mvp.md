# M7.2 — Native PDF Export MVP

## Scope

Native PDF export is an experimental DEV-only editor operation. It captures the active Markdown, `DocumentSettings`, and document title before async loading begins, builds the M7.1 semantic model, lazily imports pdfmake and the selected local font faces, and downloads one PDF Blob. At M7.2, all document families used Liberation Sans; M7.3 Phase A now resolves the selected family through the local registry documented in `docs/m7.3-font-unicode-engine.md`. The export button is disabled while generation runs. The editor displays failures and adapter diagnostics, and the object URL is revoked after download activation. The established `Export PDF` action remains `window.print()` and uses the production preview and pagination path.

The compiled-runtime smoke test builds and previews vinext separately with `DOCMARK_ENV=dev` and `DOCMARK_ENV=prod`. It checks native button availability, print availability, absence of pdfmake/font requests at editor startup, and performs a real PDF download in compiled DEV. The separate Playwright E2E commands have different environments: `playwright.dev.config.ts` runs `next dev` with `DOCMARK_ENV=dev`; `playwright.config.ts` runs `next dev` with `DOCMARK_ENV=prod`. Thus the main E2E suite is a production-environment setting on a Next development server, not a compiled production runtime. The vinext smoke checks compiled runtimes.

## Composition and diagnostics

The adapter maps headings, paragraphs, bold/italic/deletion, inline code, lists and task states, basic tables, code blocks, blockquotes, and page-break directives. Code tabs become four spaces; pdfmake's `preserveLeadingSpaces` and `preserveTrailingSpaces` retain indentation and whitespace, verified with PDF.js text positions for Python, YAML, and JSON samples. Inline code has a small color/background distinction; no advanced monospace font system is introduced.

Page size, orientation, four margins, font size, and line height are passed to pdfmake. Actual PDF line spacing is compared between two generated documents. Non-default text alignment is ignored. Every selected family, including Arial, is approximated by the embedded Liberation Sans face because no Docmark font family is embedded. Theme, cover, header, footer, and page numbers are not applied. The adapter de-duplicates warnings and distinguishes unsafe semantic link omissions from unsupported content and approximations. It always reports the limited Liberation Sans Unicode coverage; emoji and some glyphs may be missing. It does not attempt glyph detection or font fallback.

Only explicit absolute `http://` and `https://` links with an authority and without credentials, whitespace, controls, or backslashes become URI annotations. The href passed to pdfmake is the normalized URL. Unsupported or unsafe destinations retain their visible label but produce no link action. The adapter never fetches a link destination.

Images use alternative-text placeholders, TOC uses a placeholder, and Mermaid is emitted as source text. Relative and internal links are not resolved. Very long documents and visual parity with HTML pagination are not qualified. PDF/A, accessible tagged structure, signatures, and PDF.js preview are out of scope.

## PDF action inspection

The acceptance harness blocks and records cross-origin HTTP(S) requests. PDF.js validates the actual Link annotations, exact expected HTTP/HTTPS destinations, absence of JavaScript actions and attachments, and the generated PDF structure. The pypdf inspector recursively checks catalog and page trees, annotation actions, `/Next` chains, additional actions, named JavaScript entries, embedded-file trees, `/AF` and `/EF` references, file specs and file-attachment annotations. Only an explicit expected-URI allow-list is accepted. Python adversarial fixtures verify that prohibited structures and lookalike hosts are rejected by the inspector. These checks are evidence about generated PoC files, not a universal PDF security guarantee; each later renderer must have its own policy and checks.

## Reproduction and prerequisites

Prerequisites: Node.js matching the repository setup, pnpm, Playwright Chromium (or `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`), Python 3, `pypdf` (`python3 -m pip install pypdf`), and Poppler's `pdffonts`. The acceptance harness uses bundled `pdfjs-dist` to parse generated PDFs. `pdftoppm` and an image viewer are optional for visual inspection.

```sh
pnpm pdf:native:acceptance
pnpm exec playwright test --config playwright.dev.config.ts tests/e2e-dev/native-pdf.spec.ts --workers=1
pnpm test:vinext:dev
pnpm test:vinext:prod
pnpm pdf:poc:all
cd artifacts && zip -qr -FS m7.2-artifacts.zip m7.2
```

`pnpm pdf:native:acceptance` writes current case PDFs and `validation-report.json` under ignored `artifacts/m7.2/`, removing stale acceptance PDFs but preserving `editor-download.pdf`. The compiled DEV vinext smoke writes the actual compiled-runtime editor download there. The ZIP contains every current acceptance PDF, the editor download, and the report. The M7.0 reference ZIP is regenerated by `pnpm pdf:poc:all`. Generated binaries are excluded from Git.

## Validation record

The independent review correction run passed these checks, in sequence: `pnpm lint`; `pnpm exec next typegen`; `pnpm exec tsc --noEmit`; `pnpm test:unit` (243/243); `pnpm build`; `pnpm test:e2e --workers=1` (99/99); `pnpm test:e2e:dev --workers=1` (7/7); `pnpm test:vinext:dev`; `pnpm test:vinext:prod`; `pnpm pdf:native:acceptance` (15 real PDFs plus adversarial action-inspector fixtures); and `pnpm pdf:poc:all` (PDF and network assertions passed). Browser commands selected the available system Chromium through `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` because the Playwright browser bundle was unavailable in this workspace.

Both vinext commands built and ran their compiled runtime smoke checks. The local Cloudflare preview printed `Request.cf` lookup warnings because this environment could not resolve `workers.cloudflare.com`; the commands nevertheless completed successfully. The vinext builds can replace `.next/types/routes.js`, so rerun `pnpm exec next typegen` followed by `pnpm exec tsc --noEmit` before relying on TypeScript results after a vinext run. No production or Cloudflare configuration was changed to work around this behavior.

The generated `artifacts/m7.2/` set contains 15 acceptance PDFs, `editor-download.pdf`, and `validation-report.json`. `basic-document.pdf` and `code-indentation.pdf` were rendered to PNG with Poppler and visually inspected; the latter shows preserved indentation and blank lines. The browser E2E additionally verifies the editor download, snapshot consistency, diagnostics, error recovery, and unchanged print action. The generated M7.0 artifact suite also passed its collection and no-external-request assertions.

## Architecture boundary

`src/lib/document-model` remains renderer-independent. `src/lib/pdf/adapter.ts` converts it to pdfmake definitions; `generate-pdf.ts` is dynamically imported only after a DEV user action. Font bytes are same-origin static assets. No server-side document processing or remote renderer is involved. The existing HTML preview, pagination, storage, Front Matter, and print export are unchanged. No M7.3 features are included.
