# M7.2 — Native PDF Export MVP

## Scope and status

The experimental export is now connected to the editor in the DEV environment. It does not replace the existing browser Print command, and production builds do not expose the experimental control. The editor captures one Markdown, settings, and title snapshot; builds the M7.1 semantic model from that Markdown; lazily imports pdfmake; loads its four Liberation Sans font files from this application's origin; and downloads the resulting Blob. Object URLs are revoked after the browser has begun the download. A ref lock prevents repeat activation during generation. Success, failure, and adapter diagnostics are announced in the editor.

Validation completed: ESLint, Next type generation, TypeScript, 213 Vitest tests, Next build, 99/99 production E2E tests, 3/3 DEV editor export tests, vinext DEV and PROD checks, native PDF acceptance (8 PDFs), and `pnpm pdf:poc:all` passed. The first Playwright attempt could not launch its default cached browser because it was not installed in this environment; repeating with the system Chromium passed. Commands and artifacts are listed below. `artifacts/m7.2/editor-download.pdf` is the PDF downloaded through the actual editor test.

After both vinext checks, a standalone `tsc` initially failed because vinext had replaced `.next/types/routes.js` with generated types lacking Next's `AppRoutes`, `LayoutRoutes`, and `ParamMap`. Running `pnpm exec next typegen` restored the Next route types and the subsequent `pnpm exec tsc --noEmit` passed. This is a generated-artifact interaction; no project configuration was changed to hide it.

## Supported output and known limitations

The adapter maps headings, paragraphs, nested inline emphasis, ordered and unordered lists, task markers, basic tables, code, blockquotes, and explicit page breaks. Code tabs are expanded to four spaces. HTTP and HTTPS links may produce URI annotations after URL validation; relative links and internal anchors are not resolved by this renderer. Images use alternative-text placeholders, TOC uses a placeholder, and Mermaid is emitted as source. Adapter and semantic-model diagnostics are displayed after download.

The current pipeline always embeds Liberation Sans. A selected Docmark font family other than Arial is therefore reported as not preserved. Non-left text alignment, non-default line height, non-default theme, cover, headers, footers, page numbering, generated TOC, images, and rendered Mermaid diagrams are not implemented. Browser print retains the current production layout for these features. Emoji coverage is limited by Liberation Sans and no fallback is implemented. Very long documents and visual parity with the paginated HTML preview have not been qualified. Accessibility of PDF structure, PDF/A, signatures, and PDF.js preview remain out of scope.

The browser acceptance harness blocks and records cross-origin HTTP(S) requests. Its security scan traverses the generated document catalog and referenced object graph, checks name trees, page/annotation dictionaries, rejects JavaScript, embedded files, open actions, and additional actions, and allows only the expected safe URI annotations in the security fixture. This is evidence about the generated PoC PDFs, not a universal guarantee for other pdfmake definitions or future renderers. Subsequent renderers must validate their own destination and PDF action policies.

Playwright confirmed that the selected page orientation is reflected in the editor download, PDF.js can parse it and extract representative Unicode text, and the filename is normalized to `.pdf`. It also confirmed pdfmake and `/fonts/liberation/` assets are not requested on initial editor load, are loaded after explicit activation, and no cross-origin requests occur during export. A simulated font failure produces a user-visible error and a later export succeeds. The DEV button is absent in the production build, and the traditional print action still calls `window.print()`.

The vinext client build emits a separate pdfmake static chunk of about 833 kB (about 310 kB gzip); this is requested only when export is activated. The current evidence confirms lazy browser loading and that the library does not enter the Cloudflare Worker server bundle; this measurement is a client asset size, not a complete transfer-size or Worker-size benchmark.

## Reproduction and review artifacts

```sh
pnpm pdf:native:acceptance
pnpm pdf:poc:all
pnpm exec playwright test --config playwright.dev.config.ts tests/e2e-dev/native-pdf.spec.ts --workers=1
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/path/to/chromium pnpm test:e2e --workers=1
```

Playwright uses its installed Chromium by default. Set `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` only when a particular browser executable is required. Regenerate the M7.2 bundle after the commands above with `cd artifacts && zip -qr -FS m7.2-artifacts.zip m7.2`. The archive includes all eight acceptance PDFs, `validation-report.json`, and `editor-download.pdf`. The separate M7.0 archive is created by `pnpm pdf:poc:all`. Generated PDFs and ZIP files stay in ignored `artifacts/` and are not committed.

## Architecture boundary

The editor integration is a DEV-only client action. `createDocumentModel` and `buildPdfDefinition` are called from the active editor snapshot; pdfmake and Liberation font data are loaded only after the user activates Native PDF. No application server or third-party service participates. The existing `window.print()` handler, HTML preview, pagination, storage, Front Matter, and production document controls are unchanged. No M7.3 work is included.
