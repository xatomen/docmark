## Text, Unicode, and font results

The artifact audit covered 58 PDFs, 69 pages and 1,127,363 PDF bytes. pypdf strict parsing, `pdfinfo`, `pdffonts`, and Poppler extraction succeeded for every file. All production-generated PDFs embed/subset used fonts with Unicode maps. The expected blank `empty-document.pdf` is the only PDF with no text. The isolated `pdfkit-actualtext-nfd-probe.pdf` is the one font audit exception: it uses standard Helvetica without embedding or ToUnicode and is a direct PDFKit API experiment, not Docmark output.

PDF.js and Poppler both preserve the tested Spanish NFC strings as their expected Unicode code points. For tested NFD source forms, both extract NFC-composed code points. Canonical equivalence is true; exact code-point preservation is false. This is a known pdfmake/fontkit limitation. Across the full corpus, raw extraction text is not byte-identical because PDF.js joins text items and Poppler applies layout newlines. After whitespace collapse, 29/58 outputs were exact and 30/58 were NFC-canonical matches; this metric is diagnostic, not a requirement that independent extractors format spaces identically.

The Chromium PDF viewer allowed selecting and copying a Spanish sentence; pasted text matched the selection. Chromium link activation was intercepted by Playwright before network access. Reader search was not verified; do not infer it from extraction success.

## PDF security and privacy

The audit examined catalog, page, annotation, and nested action dictionaries for `/JavaScript`, `/Launch`, `/EmbeddedFiles`, `/OpenAction`, `/AA`, chained actions, file URIs and unsafe URI targets. All 58 reviewed PDFs passed; the 11 annotations use expected HTTP(S) destinations. Native generation uses local font assets. Editor startup has zero pdfmake/font requests before activation, and the acceptance request monitor observed no unexpected external HTTP(S) requests. These checks apply to the reviewed code and artifacts only; every future renderer must validate its own output and URL policy.

## Font provenance and embedding license evidence

The independent JSON audit checked 18 registered TTF assets against registry SHA-256 values and generated coverage hashes, and recorded internal names, `fsType` embedding flags, and retained license files. Unit tests now audit each registered family’s explicit attribution and license notice. Noto Sans Symbols2 was corrected using the exact Debian package `fonts-noto-core_20201225-2_all.deb` (SHA-256 `97978d09b68445fcf85342b106cd2e812d7813e3d5626f9884a5f344c3a55973`): the font’s internal notice is Copyright 2017 Google Inc.; the package carries Google Inc./Google LLC ranges. The prior incorrect Montserrat attribution header was removed, and the complete package copyright notice is retained. It found no restricted-embedding or no-subsetting flags. Liberation and Noto assets include applicable OFL notices. DejaVu Math TeX Gyre has `fsType=0x000C`; its retained Bitstream Vera license permits redistribution and embedding. The Montserrat source commit is pinned to `cc8daf2e7085006b9c112542fc82b58afc13521d`; the included OFL text matches the upstream license after normalizing trailing whitespace, and the four static instances regenerated byte-for-byte using fontTools 4.61.1. Their internal family is renamed to Docmark Signature Sans to respect the OFL reserved-name restriction.

Full asset hashes, package/source evidence, and font metadata are retained in `artifacts/m7.3/phase-e/font-license-audit.json`.

## Performance observations

The final Playwright DEV measurement saw 34 editor startup resources and no pdfmake or PDF font request before export. Cold primary-Latin export loaded one 410,820-byte Liberation Sans face and 3,547,990 bytes of pdfmake chunks (3,958,810 bytes total observed in that scenario), generated a 7,006-byte PDF, and took about 408 ms. The tested math and pictograph fallbacks transferred 577,192 and 656,852 font bytes. A multi-face export requested 1,239,596 font bytes; two subsequent repeats requested no new font files. The mixed export generated a 30,645-byte PDF. These values are local DEV observations, not budgets or production benchmarks. pdfmake retains decoded VFS font buffers for the browser session; Docmark caches/reuses fetched face bytes and has no supported eviction mechanism. There was no Worker bundle-size measurement.

## Remaining limitations and recommendation

NFD text is canonically composed in PDF extraction. Broad CJK/RTL/Indic shaping, bidi reading order, complex emoji sequences, and verified visual fallback are not provided. Acrobat, Firefox, Edge, and PDF-viewer search were unavailable for testing. Font sizes/timings are environment-specific and do not establish production/Worker budgets. Renderer-specific URL validation remains each later renderer’s responsibility.

These are documented limitations for subsequent product decisions, not newly discovered regressions or blockers to review the current font/Unicode engine. M7.3 Phase E is complete within scope. The recommendation is to proceed to independent code review; M7.4 has not started.
