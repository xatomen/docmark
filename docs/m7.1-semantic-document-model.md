# M7.1 semantic document model — work in progress

`createDocumentModel` parses Markdown with the existing unified, remark-parse and remark-gfm packages into serializable discriminated unions. The module is isolated from the editor, DOM, pagination and PDF engines. It accepts existing DocumentSettings and can invoke the existing portable Markdown parser for front matter. IDs are deterministic within a model; code and Mermaid contain parser-preserved source, not necessarily byte-exact input.

Example: `# Hello` produces a heading block with depth 1, ID `heading-0`, and a text child `Hello`. Explicit top-level `:::toc` and `:::pagebreak` directives become semantic blocks. Mermaid fences retain source without rendering. Tables contain alignment and rows of inline cells. Unknown nodes and raw HTML produce diagnostics; their raw content is not executed.

This is an initial implementation, not a completed milestone. Heading identifiers are not yet aligned with preview TOC rules, reference-style links and definitions need handling, URL sanitization and anchor resolution are not yet implemented, soft line breaks remain embedded in text, and table header semantics and portable metadata diagnostics require further work. Do not connect this model to production rendering until these gaps and compatibility tests are resolved.

## Reference and URL work in progress

Definitions are collected before transforming links, allowing forward reference definitions. Links distinguish fragments, relative and external URLs; unsafe protocols are checked against the existing rehype-sanitize default schema. Images use the schema's `src` protocols and are never fetched. Invalid targets produce diagnostics. Table blocks now separate `header` cells from body `rows` and preserve column alignment.

The existing preview does not implement heading slugs: it emits sequential `data-docmark-heading-id` values for nonempty H1–H3 only when a TOC is present. The present semantic IDs use the same prefix but currently apply to all headings irrespective of TOC and label; they are therefore **not preview-compatible**. Semantic fragment resolution currently matches these IDs and must not be treated as HTML anchor parity. Definitions that Remark parses as literal text when unresolved cannot currently produce diagnostics. Protocol handling requires further security review for control characters and relative URL edge cases before production use.

## Latest validation and remaining work

Semantic heading IDs now use `heading-N`, while `anchorId` is populated for nonempty H1–H3 only when a top-level TOC exists; `tocEligible` is independent of TOC presence. A parity test compares these anchor IDs to rendered HTML for duplicate, Unicode, empty and deeper headings. An undefined reference interpreted by Remark as text remains literal and does not produce a diagnostic. A recognized fragment without an anchor produces a diagnostic.

URL validation consults `rehype-sanitize` protocol lists and additionally rejects ASCII whitespace/control characters and backslashes. It does not fetch resources. This is deliberately stricter than the production HTML pipeline and needs full browser interpretation and adversarial coverage before a renderer consumes it. Percent encoding, character references and all requested URL edge cases are not yet comprehensively tested. The renderer must still treat model data as untrusted.

Validation: ESLint, Next type generation, TypeScript, 178 unit tests, Next build, 98 Playwright tests (one worker), vinext DEV and vinext PROD passed. Unit coverage remains incomplete for the full requested URL and heading parity matrix; this milestone is not yet ready for independent review.

## Acceptance coverage

The Markdown-to-model URL matrix tests links and images separately for unsafe `javascript`, `vbscript`, mixed case, `data`, entity-encoded tabs, carriage returns, line feeds, ASCII controls, boundary spaces and backslashes. Remark interprets character references before the model checks the resulting destination. HTTP, HTTPS, relative and root-relative paths, protocol-relative destinations, fragments, Unicode paths and ordinary percent-encoded paths are preserved; `mailto` is accepted for links and rejected for images in accordance with the sanitizer schema. An encoded spelling followed by a literal colon is not treated as a permitted scheme. The model does not repeatedly percent-decode URLs. Renderers must independently validate destinations in their own security context; these tests do not establish universal URL safety.

Heading parity tests compare the actual HTML renderer with zero, one and multiple TOC directives, H1–H6, empty and duplicate headings, accents, Unicode, punctuation and nested formatting. Semantic `heading-N` identities are deterministic and independent of TOC presence. `anchorId` follows the legacy preview's TOC-dependent identifiers; `tocEligible` records eligibility independently. Forward fragments are resolved after heading collection and missing targets receive diagnostics. These identifiers are not a general slug system.

The final unit matrix contains 203 passing tests. Prior end-to-end validation yielded 98/98 Playwright tests and successful vinext DEV/PROD checks; those integration checks were not rerun for this test-and-documentation-only change. Previously noted unsupported-node and unresolved literal-reference limitations remain.
