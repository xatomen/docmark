# M7.1 — Semantic document model

`createDocumentModel(markdown, options)` builds a serializable, renderer-independent representation using the existing remark parser and GFM plugin. It remains isolated from production rendering and does not use the DOM, pdfmake, layout measurements or network access. It accepts existing `DocumentSettings`; the optional `parseFrontMatter` mode uses the existing Markdown file parser and reports its warning as a `frontMatter` diagnostic. Explicit settings take precedence over parsed settings.

Blocks include paragraphs, headings, blockquotes, lists with nested items and task state, tables, code, Mermaid source, thematic breaks and the existing top-level TOC/page-break directives. Inline content represents text, code, emphasis, links and images. Code preserves parser output, not necessarily byte-exact Markdown. Tables use a separate header and body: each row has the header's column count, missing cells are empty and excess cells are discarded, following the renderer's GFM table behavior.

Semantic heading IDs (`heading-N`) are deterministic within one model. `tocEligible` records nonempty H1–H3 eligibility regardless of a TOC; `anchorId` mirrors the preview's sequential `docmark-heading-N` identifiers when a TOC exists. Fragment links preserve their original URL and resolve `targetId` to the semantic heading ID rather than the renderer-specific anchor. Missing anchors produce diagnostics. The model does not invent heading slugs or page numbers.

Reference definitions are collected recursively in source order with normalized identifiers and first-definition precedence. Reference links and images preserve titles and formatting. Undefined syntax which Remark parses as literal text stays literal; actual unresolved reference nodes produce diagnostics. Raw HTML and other unsupported nodes are not executed and produce diagnostics.

URL protocols are checked against the existing `rehype-sanitize` defaults for `href` and `src`; ASCII whitespace and controls and backslashes are additionally rejected. Relative paths, fragments and protocol-relative URLs are supported. No repeated percent decoding or resource fetching occurs. This is not a guarantee of universal URL safety: future renderers must validate destinations according to their own execution context.

For example, `[go](#docmark-heading-0)` before `:::toc` and `# Title` resolves to semantic `targetId: "heading-0"`; the heading retains `anchorId: "docmark-heading-0"`. A GFM table exposes `header` separately from `rows`, preserving each cell's inline structure and column alignment.

Tests exercise the M7.0 fixture, determinism, nested structures, front matter warnings, references, URL categories, anchor compatibility and table normalization. Prior M7.1 application validation passed Next build, 98 Playwright cases (one worker) and vinext DEV/PROD. Subsequent correction validation is reported in the PR. Future M7.2 adapters must map semantic IDs and revalidate untrusted URLs; native PDF export is not implemented here.
